# Battery measurement context

Verified 2026-11-18 during the power review; see [review](../battery-power-review.md) and [video readings](../battery-video-measurements.md).

- User reports an added switch interrupting battery negative; it is not drawn in the checked schematic.
- The three root videos (`deep-sleep.mp4`, `light-sleep-screen.mp4`, `lightsleep.mp4`) were recorded with the battery switched off, supply connected to USB, and joystick off. `screen` means OLED on; `lightsleep.mp4` has OLED off.
- Those readings concern USB input through the TP4056 module, not battery current. Do not use them as measured battery autonomy or MCU deep-sleep current. The source display has approximately 1 mA resolution if its current units are A.
- Schematics show HT7333-3 after the TP4056 module, a permanently supplied MCP23S17 and OLED, and STM32F030F4P6 in the joystick. Its potentiometer supply is PA0. Verify fitted parts before assigning component currents.
- Static review confirmed that local ESP-IDF v5.5 disables timer wake-up when automatic light sleep is turned off by esp_pm_configure; stm32f0xx-hal 0.18 powers ADC down after each OneShot read. Avoid reporting either as a missing shutdown without checking the actual dependency version.
- Firmware 0.2.20 addresses findings 1 and 2 in the review (2026-11-18). A BLE host being accepted or disconnected prompts the main loop to recalculate the deep-sleep deadline from the start of the same idle period. OLED shutdown now sends `set_display_on(false)` directly. The review describes the behavior of 0.2.19.
- Firmware 0.2.21 retries a failed OLED-off command once before deep sleep (2026-11-18). A postponed sleep renews the retry budget for an OLED that failed to turn off. After two consecutive failures, it logs the errors and enters deep sleep.
- Firmware 0.2.22 blanks OLED RAM on boot while the panel is off (2026-11-19). The locked ssd1306 0.8.4 driver enables the panel during `init()`, so the blank frame replaces any retained frame before that call. The display thread enables the panel with its first drawn frame.
- Firmware 0.2.23 preserves the OLED state and its deadlines if deep sleep is canceled (2026-11-19). The sleep deadline uses the accepted-host state published by `Link`. The final sleep decision is serialized with BLE and HID work admission, and queued OTA commands hold a reservation through completion. A quiet configuration session expires under the existing HID timeout.
- Firmware 0.2.24 routes host-change notifications from the asynchronous BLE callbacks (2026-11-19). Profile commands run on the main task and need no notification to itself. Sleep eligibility is checked before OLED preparation and again after PM and GPIO preparation, immediately before committing. A failed OLED-off command gets a separate check before retrying.
- Firmware 0.2.25 gives each BLE connection a generation and routes deferred HID replies to the accepted connection that submitted the request (2026-11-20). The sleep coordinator accounts for the accepted host, the existing HID session timeout, queued or running config and OTA work, and OTA boot verification. A canceled sleep restores automatic light sleep, GPIO wake configuration, and OLED drawing. Hardware validation is pending.
- Verified against the local ESP-IDF 5.5 sources on 2026-11-20. On ESP32-C3, `esp_deep_sleep_start()` forces sleep even if a wake source has already asserted. `esp_deep_sleep_try_to_start()` enables rejection, and GPIO is in the C3 sleep-reject mask. A GPIO level check before the SDK call leaves a window before the hardware enters sleep.
- The same ESP-IDF 5.5 source check shows that `esp_deep_sleep_try_to_start()` runs the PHY sleep callbacks before checking hardware rejection. With global deep-sleep GPIO hold enabled, it also isolates unheld digital pads before that check. The firmware's pre-commit cancellation path restores wake IRQs, light sleep, and OLED drawing. Rejection from inside ESP-IDF requires checking recovery of SPI, I2C, and BLE on the board as well.
- Firmware 0.2.26 uses the BLE link's existing pairing deadline to postpone deep sleep for eligible connections (2026-11-20). Once authorization starts, the callback's reservation covers it through completion. Accepting a host uses the connected timeout from the original idle start.
